# Journal 005: Player-driven floors, LPC characters and checked releases

September 20, 2026. The owner wanted each player's route to shape the board instead of a repeating random collapse schedule. A living participant now starts an irreversible 1.8-second timer on the tile under their center. Untouched tiles stay safe. Removing the overall round deadline and final-island schedule lets movement determine the finish. The server still decides every collapse, elimination and score; disconnected characters remain vulnerable.

Readiness was removed at the owner's request. The host starts once two players are connected, and the arena takes over most of the screen during countdown and play. Results restore the lobby and cumulative scores. Browser acceptance caught Phaser retaining an old parent size after the layout changed; explicitly measuring its parent before refreshing FIT scaling fixed the canvas transition. Narrow phone layouts also needed more compact lobby spacing.

The supplied Universal LPC sheet replaces the temporary drawn characters. The original PNG is preserved, with directional walk/idle frames and a one-shot fall animation. Stable colored ground markers, numbered badges and the local ring keep identical artwork usable in a party of twelve. Facing follows local intent to avoid small prediction corrections flipping the character. Restoring an already-eliminated character uses the final fall pose, and reduced-motion mode uses still frames. The complete upstream credit catalog is available from the footer without being downloaded during normal play.

The owner also requested a branch-based release workflow. Development lives on `codex/test`; GitHub Actions runs the rule, session, twelve-player, browser and production checks. A pull request promotes tested work to `main`, whose successful checks permit the existing Free Render service to deploy automatically. That merge is a release action and should happen between games, because redeployment loses in-memory parties and scores. No second test service or paid runner is needed.

Local production acceptance passed before publishing the workflow. An independent code review found no concrete blocker. The first Linux CI run exposed a test assumption: reconnecting the session does not mean the lazy renderer and sprite preload have finished. Browser checks now wait for a first rendered character before comparing scene/listener counts or deliberately restarting a playable party. This keeps the checks tied to the state they intend to exercise, without fixed sleeps or relaxed assertions. The two affected browser cases passed locally after that correction.

Remote CI and deployment evidence belong in [verification](../docs/verification.md) and the initial release pull request. Physical-phone and human playtests remain separate from browser emulation. Audio remains a possible future addition; this change does not add sound files or playback.
